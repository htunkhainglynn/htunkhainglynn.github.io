## Braille နှင့် Binary Code များ

စာအရေးအသားထဲက အက္ခရာတွေကို နားလည်လို့ရတဲ့ code တစ်ခုအဖြစ် အောင်အောင်မြင်မြင် ပြောင်းခဲ့တဲ့ ပထမဆုံးလူဟာ Samuel Morse မဟုတ်ဘူး။ ကိုယ့်နာမည်ထက် ကိုယ်တီထွင်ခဲ့တဲ့ code နာမည်နဲ့ ပိုပြီး အမှတ်ရခံရတဲ့ ပထမဆုံးလူလည်း သူမဟုတ်ဘူး။ အဲဒီဂုဏ်ကတော့ Morse မွေးပြီး ၁၈ နှစ်လောက်အကြာမှာ မွေးလာတဲ့ မျက်မမြင် ပြင်သစ်လူငယ်တစ်ယောက်နဲ့ ပိုထိုက်တန်တယ်။ သူက အသက်ငယ်ငယ်နဲ့တင် ထင်ရှားတဲ့ အမှတ်အသားတစ်ခု ချန်ထားနိုင်ခဲ့သူပါ။ သူ့ဘဝအကြောင်း သိထားတာ မများပေမယ့် သိရသလောက်နဲ့တင် စိတ်ဝင်စားဖို့ကောင်းတဲ့ ဇာတ်လမ်းတစ်ပုဒ် ဖြစ်နေပြီ။

Louis Braille ကို ၁၈၀၉ ခုနှစ်မှာ Paris မြို့အရှေ့ဘက် ၂၅ မိုင်လောက်ဝေးတဲ့ ပြင်သစ်နိုင်ငံ Coupvray ရွာမှာ မွေးခဲ့တယ်။ သူ့အဖေက မြင်းတန်ဆာပစ္စည်းတွေ လုပ်တဲ့သူ။ Louis အသက် ၃ နှစ်အရွယ်—ကလေးငယ်တွေ အဖေ့အလုပ်ရုံထဲ ဝင်မဆော့သင့်သေးတဲ့အရွယ်—မှာ ချွန်ထက်တဲ့ကိရိယာတစ်ခုနဲ့ မျက်စိကို မတော်တဆ ထိုးမိခဲ့တယ်။ ဒဏ်ရာက ပိုးဝင်ပြီး နောက်မျက်စိတစ်ဖက်ဆီပါ ကူးသွားတာကြောင့် လုံးဝမျက်မမြင် ဖြစ်သွားတယ်။ အဲဒီခေတ်မှာ ဒီလိုကံကြမ္မာမျိုး ကြုံရသူအများစုဟာ ပညာမတတ်၊ ဆင်းရဲနွမ်းပါးတဲ့ဘဝနဲ့ပဲ နေသွားရဖို့ များတယ်။ ဒါပေမယ့် Louis လေးရဲ့ ဉာဏ်ကောင်းမှုနဲ့ သင်ယူချင်စိတ်ကို လူတွေ မကြာခင် သတိထားမိလာကြတယ်။ ရွာဘုန်းတော်ကြီးနဲ့ ဆရာတစ်ယောက်တို့ ကူညီပေးလို့ အစမှာ ရွာက တခြားကလေးတွေနဲ့အတူ ကျောင်းတက်ခဲ့ပြီး အသက် ၁၀ နှစ်ရောက်တော့ Paris မြို့က Royal Institution for Blind Youth ကို ပို့ပေးခဲ့ကြတယ်။

မျက်မမြင်ကလေးတွေ ပညာသင်ရာမှာ အကြီးဆုံးအတားအဆီးက ပုံနှိပ်စာအုပ်တွေကို မဖတ်နိုင်တာပဲ။ Paris က မျက်မမြင်ကျောင်းကို တည်ထောင်ခဲ့တဲ့ Valentin Haüy (၁၇၄၅–၁၈၂၂) က စာလုံးတွေကို ကြီးကြီးဝိုင်းဝိုင်း font နဲ့ စာရွက်ပေါ် ဖောင်းကြွအောင်လုပ်ပြီး လက်နဲ့စမ်းဖတ်နိုင်တဲ့ စနစ်တစ်ခု တီထွင်ထားခဲ့တယ်။ ဒါပေမယ့် ဒီစနစ်က သုံးရအလွန်ခက်ပြီး ဒီနည်းနဲ့ ထုတ်ထားတဲ့ စာအုပ်လည်း နည်းနည်းပဲရှိတယ်။

မျက်စိမြင်သူ Haüy ဟာ အတွေးပုံစံဟောင်းတစ်ခုထဲမှာ ပိတ်မိနေခဲ့တယ်။ သူ့အတွက် A က A ပဲ၊ ဒါကြောင့် A အက္ခရာဟာ A နဲ့တူအောင် မြင်ရမယ်—ဒါမှမဟုတ် လက်နဲ့စမ်းမိရမယ်—လို့ ယူဆထားတယ်။ (ဓာတ်မီးနဲ့ ဆက်သွယ်ခိုင်းခဲ့ရင်လည်း အရင်က ကျွန်တော်တို့ စမ်းခဲ့သလို လေထဲမှာ အက္ခရာပုံတွေ ဆွဲပြဖို့ သူကြိုးစားမိလောက်တယ်။ အဲဒီနည်း အလုပ်သိပ်မဖြစ်တာကိုတော့ ကျွန်တော်တို့ သိပြီးသားပေါ့။) ဖောင်းကြွအက္ခရာပုံနဲ့ လုံးဝမတူတဲ့ code တစ်မျိုးက မျက်မမြင်သူတွေအတွက် ပိုသင့်တော်နိုင်တယ်ဆိုတာ Haüy မစဉ်းစားမိခဲ့ပုံရတယ်။

အစားထိုး code တစ်မျိုးရဲ့ အစကတော့ လုံးဝမမျှော်လင့်ထားတဲ့နေရာက လာတယ်။ ပြင်သစ်စစ်တပ်က ဗိုလ်ကြီး Charles Barbier ဟာ ၁၈၁၅ ခုနှစ်အရောက်မှာ နောက်ပိုင်း écriture nocturne၊ ဒါမှမဟုတ် “ညဘက်စာရေးနည်း” လို့ခေါ်လာတဲ့ စနစ်တစ်ခုကို တီထွင်ထားခဲ့တယ်။ စက္ကူထူပေါ်မှာ ဖောင်းကြွအစက်ပုံစံတွေ သုံးတဲ့ဒီစနစ်ကို တိတ်တိတ်နေရမယ့် အမှောင်ထဲမှာ စစ်သားအချင်းချင်း စာတိုပို့ဖို့ ရည်ရွယ်ထားတာ။ စစ်သားတွေက စူးနဲ့တူတဲ့ stylus ကိုသုံးပြီး စာရွက်ရဲ့ နောက်ဘက်ကနေ အစက်တွေ ထိုးနိုင်တယ်။ ရလာတဲ့ ဖောင်းကြွအစက်တွေကို လက်ချောင်းနဲ့ စမ်းဖတ်လို့ရတယ်။

Louis Braille ဟာ အသက် ၁၂ နှစ်မှာ Barbier ရဲ့ စနစ်ကို သိလာတယ်။ ဖောင်းကြွအစက်တွေကို လက်နဲ့ဖတ်ရလွယ်တာသာမက ရေးရလည်းလွယ်တာကို သူသဘောကျတယ်။ စာရွက်နဲ့ stylus ရှိတဲ့ ကျောင်းသားတစ်ယောက်ဟာ အတန်းထဲမှာ ကိုယ်တိုင်မှတ်စုရေးပြီး နောက်မှ ပြန်ဖတ်နိုင်တယ်။ Braille က ဒီစနစ်ကို ပိုကောင်းလာအောင် မနားမနေ ကြိုးစားခဲ့ပြီး သုံးနှစ်အတွင်း—အသက် ၁၅ နှစ်မှာ—ဒီနေ့အထိ အခြေခံသဘောတရားတွေ ဆက်သုံးနေဆဲဖြစ်တဲ့ သူ့ကိုယ်ပိုင်စနစ်ကို ဖန်တီးနိုင်ခဲ့တယ်။ နှစ်ပေါင်းများစွာ ဒီစနစ်ကို ကျောင်းထဲမှာပဲ သိခဲ့ကြပေမယ့် နောက်တော့ တဖြည်းဖြည်း ကမ္ဘာအနှံ့ ပျံ့သွားတယ်။ ၁၈၃၅ ခုနှစ်မှာ Louis Braille တီဘီရောဂါ စွဲကပ်ခဲ့ပြီး ၁၈၅၂ ခုနှစ်၊ အသက် ၄၃ နှစ်ပြည့်ပြီး မကြာခင်မှာ အဲဒီရောဂါနဲ့ပဲ ကွယ်လွန်ခဲ့တယ်။

ဒီနေ့မှာတော့ Braille စနစ်ရဲ့ မူကွဲအမျိုးမျိုးနဲ့ audiobook တွေဟာ မျက်မမြင်သူတွေ စာအရေးအသားကို လက်လှမ်းမီနိုင်ဖို့ နည်းလမ်းတွေ ပေးနေကြတယ်။ ဒါပေမယ့် Braille ဟာ တန်ဖိုးမဖြတ်နိုင်တဲ့ စနစ်တစ်ခုအဖြစ် ဆက်ရှိနေသေးပြီး မျက်စိလည်းမမြင်၊ နားလည်းမကြားသူတွေအတွက်တော့ စာဖတ်နိုင်မယ့် တစ်ခုတည်းသောနည်းလမ်းပဲ။ မကြာသေးခင် ဆယ်စုနှစ်တွေမှာ elevator တွေနဲ့ ATM စက်တွေကို လူတိုင်း ပိုလွယ်လွယ်ကူကူ သုံးနိုင်အောင် Braille ထည့်သုံးလာကြတာကြောင့် သာမန်လူတွေပါ Braille နဲ့ ပိုရင်းနှီးလာကြတယ်။

ဒီအခန်းမှာ Braille code ကို အစိတ်အပိုင်းခွဲပြီး ဘယ်လိုအလုပ်လုပ်သလဲဆိုတာ ကြည့်မယ်။ Braille ကို တကယ်သင်ယူဖို့လည်း မလိုဘူး၊ ဘာမှအလွတ်ကျက်စရာလည်း မရှိဘူး။ ဒီလေ့လာမှုရဲ့ တစ်ခုတည်းသောရည်ရွယ်ချက်က code တွေရဲ့ သဘောသဘာဝကို နောက်ထပ်တစ်ဆင့် နားလည်လာဖို့ပဲ။

Braille မှာ ပုံမှန်စာအရေးအသားထဲက သင်္ကေတတိုင်း—အထူးသဖြင့် အက္ခရာ၊ ဂဏန်းနဲ့ ပုဒ်ဖြတ်ပုဒ်ရပ်တိုင်း—ကို အလျား ၂ စက်၊ အမြင့် ၃ စက်ပါတဲ့ cell တစ်ခုအတွင်းက ဖောင်းကြွအစက်တစ်ခု ဒါမှမဟုတ် တစ်ခုထက်ပိုတဲ့ အစက်တွေနဲ့ encode လုပ်ထားတယ်။ Cell ထဲက အစက်တွေကို ပုံမှန်အားဖြင့် ၁ ကနေ ၆ အထိ နံပါတ်တပ်ထားတယ်။

Braille အစက်တွေကို စာရွက်ပေါ် ဖောင်းကြွလာအောင် ရိုက်နိုင်တဲ့ အထူးလက်နှိပ်စက်တွေ တီထွင်ခဲ့ကြတယ်။ ဒီနေ့ခေတ်မှာတော့ computer နဲ့ထိန်းချုပ်တဲ့ embosser စက်တွေက ဒီအလုပ်ကို လုပ်ပေးတယ်။

ဒီစာအုပ်ထဲက စာမျက်နှာနှစ်မျက်နှာလောက်ကိုပဲ Braille နဲ့ ဖောင်းကြွအောင်လုပ်မယ်ဆိုရင်တောင် ကုန်ကျစရိတ် အလွန်များသွားမယ်။ ဒါကြောင့် ပုံနှိပ်စာမျက်နှာပေါ်မှာ Braille ကို ဖော်ပြလေ့ရှိတဲ့ သင်္ကေတနည်းတစ်ခုကို ဒီမှာသုံးထားတယ်။ ဒီနည်းမှာ cell ထဲက အစက် ၆ ခုလုံးကို ပြထားတယ်။ အစက်ကြီးတွေက စာရွက်ဖောင်းကြွနေတဲ့ နေရာတွေဖြစ်ပြီး အစက်သေးတွေက ပြားနေတဲ့နေရာတွေကို ဆိုလိုတယ်။ ဥပမာ အောက်က Braille သင်္ကေတမှာ—

ဒီအချိန်မှာ ကျွန်တော်တို့အတွက် စိတ်ဝင်စားစရာက ဒီအစက်တွေဟာ binary ဖြစ်နေတာပဲ။ အစက်တစ်ခုဟာ ပြားနေတာ ဒါမှမဟုတ် ဖောင်းနေတာ—နှစ်မျိုးထဲက တစ်မျိုးပဲ ဖြစ်နိုင်တယ်။ ဒါကြောင့် Morse code နဲ့ binary ပေါင်းစပ်မှုတွေအကြောင်း သင်ယူခဲ့တာကို Braille မှာလည်း အသုံးချနိုင်တယ်။ အစက် ၆ ခုရှိပြီး တစ်ခုစီက ပြားနိုင်၊ ဖောင်းနိုင်တာကြောင့် ဖြစ်နိုင်တဲ့ ပေါင်းစပ်ပုံစုစုပေါင်းဟာ ၂ × ၂ × ၂ × ၂ × ၂ × ၂၊ ဒါမှမဟုတ် ၂⁶၊ တစ်နည်းအားဖြင့် ၆၄ မျိုး ရှိတယ်။

ဒါကြောင့် Braille စနစ်က မတူတဲ့ code ၆၄ မျိုးအထိ ကိုယ်စားပြုနိုင်တယ်။ ဒီမှာ ၆၄ မျိုးလုံးကို ပြထားတယ်။

Braille code ကို စခွဲကြည့်ဖို့ အခြေခံ lowercase အက္ခရာတွေကနေ စကြစို့။

စကားလုံးတစ်လုံးထဲက အက္ခရာတစ်လုံးစီရဲ့ cell ကြားမှာ နေရာနည်းနည်း ခြားထားတာကို သတိထားကြည့်ပါ။ စကားလုံးတစ်လုံးနဲ့တစ်လုံးကြားမှာတော့ ပိုကျယ်တဲ့နေရာ—တစ်နည်းအားဖြင့် ဖောင်းကြွအစက်တစ်ခုမှမပါတဲ့ cell တစ်ခုစာ—ခြားထားတယ်။

ဒါဟာ Louis Braille တီထွင်ခဲ့တဲ့ Braille ရဲ့ အခြေခံပဲ—အနည်းဆုံး Latin အက္ခရာတွေအတွက်တော့ ဒီလိုပဲ။ ပြင်သစ်ဘာသာမှာ သုံးလေ့ရှိတဲ့ accent ပါတဲ့ အက္ခရာတွေအတွက်လည်း Louis Braille က code တွေ ဖန်တီးခဲ့တယ်။ Classical French မှာ မသုံးတဲ့ w အတွက် code မရှိတာကို သတိထားမိမယ်။ (စိတ်မပူပါနဲ့။ နောက်တော့ w ပေါ်လာမှာပါ။) ဒီအဆင့်အထိ ဖြစ်နိုင်တဲ့ code ၆၄ မျိုးထဲက ၂၅ မျိုးကိုပဲ သုံးရသေးတယ်။

Lowercase အက္ခရာ ၂၅ လုံးအတွက် Braille code တွေကို သေချာကြည့်လိုက်ရင် ပုံစံတစ်ခု တွေ့မယ်။ ပထမတန်းက a ကနေ j အထိ အက္ခရာတွေမှာ cell ရဲ့ အပေါ်ဘက်နေရာ ၄ ခု—အစက် ၁၊ ၂၊ ၄ နဲ့ ၅—ကိုပဲ သုံးထားတယ်။ ဒုတိယတန်းက k ကနေ t အထိဟာ ပထမတန်းကို အစက် ၃ ထပ်ဖောင်းထားတာကလွဲရင် အတူတူပဲ။ တတိယတန်းက u ကနေ z အထိမှာတော့ အစက် ၃ နဲ့ ၆ နှစ်ခုလုံး ထပ်ဖောင်းထားတယ်။

Louis Braille က သူ့စနစ်ကို လက်နဲ့ထိုးရေးဖို့ မူလက ဒီဇိုင်းလုပ်ခဲ့တာ။ ဒီလိုထိုးရင် အလွန်တိကျမှာမဟုတ်ဘူးဆိုတာ သူသိတယ်။ ဒါကြောင့် မရှင်းမလင်းဖြစ်နိုင်တာကို လျှော့ချဖို့ lowercase အက္ခရာ ၂၅ လုံးကို လိမ္မာပါးနပ်စွာ သတ်မှတ်ခဲ့တယ်။ ဥပမာ ဖြစ်နိုင်တဲ့ Braille code ၆၄ မျိုးထဲမှာ ဖောင်းကြွအစက်တစ်ခုတည်းပါတဲ့ code ၆ မျိုးရှိတယ်။ ဒါပေမယ့် lowercase အက္ခရာအတွက် တစ်မျိုးတည်း—အက္ခရာ a—ကိုပဲ သုံးထားတယ်။ ဒေါင်လိုက်ကပ်လျက် အစက်နှစ်ခုပါတဲ့ code ၄ မျိုးရှိပေမယ့် b အတွက် တစ်မျိုးတည်းကိုပဲ သုံးတယ်။ ရေပြင်ညီကပ်လျက် အစက်နှစ်ခုပါတဲ့ code ၃ မျိုးထဲကလည်း c အတွက် တစ်မျိုးတည်းကိုပဲ သုံးထားတယ်။

Louis Braille တကယ်သတ်မှတ်ခဲ့တာက စာမျက်နှာပေါ်မှာ နည်းနည်းရွေ့နေခဲ့ရင်တောင် အဓိပ္ပာယ်မပြောင်းတဲ့ ထူးခြားပုံသဏ္ဌာန်အစုတစ်ခုပါ။ a ဆိုတာ ဖောင်းကြွအစက်တစ်ခု၊ b ဆိုတာ ဒေါင်လိုက်ကပ်လျက် အစက်နှစ်ခု၊ c ဆိုတာ ရေပြင်ညီကပ်လျက် အစက်နှစ်ခု—ဒီလိုနဲ့ ဆက်သွားတယ်။

Code တွေမှာ အမှားဝင်လွယ်တတ်တယ်။ Code ကို ရေးနေတုန်းဖြစ်တဲ့အမှား—ဥပမာ Braille သင်ယူသူတစ်ယောက် စာရွက်ပေါ် အစက်တွေ ထိုးနေတုန်း မှားတာ—ကို encoding error လို့ခေါ်တယ်။ Code ကို ဖတ်တဲ့အခါ မှားတာကို decoding error လို့ခေါ်တယ်။ ဒါ့အပြင် transmission error လည်း ရှိနိုင်တယ်။ ဥပမာ Braille ပါတဲ့ စာမျက်နှာတစ်ခု ပျက်စီးသွားတာမျိုးပေါ့။

ပိုရှုပ်ထွေးတဲ့ code တွေမှာ အမှားတွေကို ရှာဖွေပြင်ဆင်နိုင်ဖို့ နည်းလမ်းအမျိုးမျိုးကို စနစ်ထဲမှာ တစ်ခါတည်း ထည့်တည်ဆောက်ထားလေ့ရှိတယ်။ ဒီသဘောနဲ့ကြည့်ရင် Louis Braille မူလသတ်မှတ်ခဲ့တဲ့ Braille ဟာ အဆင့်မြင့် coding စနစ်တစ်ခုပါပဲ။ အစက်တွေထိုးတဲ့အခါနဲ့ ဖတ်တဲ့အခါ တိကျမှုနည်းနည်း လွဲနိုင်တာကို ခံနိုင်အောင် redundancy—လိုတာထက် အချက်အလက်နည်းနည်းပိုထည့်ထားခြင်း—ကို အသုံးချထားတယ်။

Louis Braille ခေတ်နောက်ပိုင်းမှာ သင်္ချာနဲ့ ဂီတကို မှတ်သားဖို့ စနစ်တွေအပါအဝင် Braille code ကို နည်းအမျိုးမျိုးနဲ့ ချဲ့ထွင်ခဲ့ကြတယ်။ အခု ပုံနှိပ်ထုတ်ဝေတဲ့ English စာသားတွေမှာ အများဆုံးသုံးတာကို Grade 2 Braille လို့ခေါ်တယ်။ Grade 2 Braille က စာရွက်သုံးစွဲမှု လျှော့ချပြီး ဖတ်နှုန်းမြန်စေဖို့ အတိုကောက်အများကြီး သုံးတယ်။ ဥပမာ အက္ခရာ code တစ်ခုက သူ့ဘာသာ တစ်လုံးတည်းရပ်နေရင် အများသုံးစကားလုံးတစ်လုံးကို ကိုယ်စားပြုတယ်။ အောက်က တန်းသုံးတန်း—တတိယတန်းကို ပြည့်စုံအောင် ဖြည့်ထားတာပါအပါအဝင်—မှာ ဒီစကားလုံး code တွေကို ပြထားတယ်။

ဒီထဲက ပထမ code လေးခုက comma၊ semicolon၊ colon နဲ့ period တို့ပဲ။ ဘယ်ဘက်ကွင်းနဲ့ ညာဘက်ကွင်းအတွက် code တစ်ခုတည်း သုံးထားပေမယ့် အဖွင့် quotation mark နဲ့ အပိတ် quotation mark အတွက်တော့ code နှစ်ခုခွဲထားတာကို သတိထားပါ။ ဒီ code တွေကို a ကနေ j အထိ အက္ခရာတွေနဲ့ မှားနိုင်တာကြောင့် တခြားအက္ခရာတွေ ဝန်းရံနေတဲ့ အကြောင်းအရာတစ်ခုလုံးထဲမှာမှ အဓိပ္ပာယ်ရှင်းလာတယ်။

အခုဆို code ၅၁ မျိုးအထိ ရောက်လာပြီ။ အောက်က code ၆ မျိုးကတော့ မသုံးရသေးတဲ့ အစက် ၃၊ ၄၊ ၅ နဲ့ ၆ ပေါင်းစပ်ပုံအမျိုးမျိုးကို သုံးပြီး အတိုကောက်တွေနဲ့ နောက်ထပ်ပုဒ်ဖြတ်ပုဒ်ရပ်တချို့ကို ကိုယ်စားပြုထားတယ်။

![C.O.D.E အခန်း ၃ — အခုဆို code ၅၁ မျိုးအထိ ရောက်လာပြီ။ အောက်က code ၆ မျိုးကတော့ မသုံးရသေးတဲ့ အစက် ၃၊ ၄၊ ၅ နဲ့ ၆ ပေါင်းစပ်ပုံအမျို](/images/blog/code-chapter-3/image12.jpg)

“ble” အတွက် code က အလွန်အရေးကြီးတယ်။ စကားလုံးတစ်လုံးရဲ့ အစိတ်အပိုင်းမဟုတ်ဘဲ သီးသန့်ပေါ်လာရင် နောက်က code တွေကို ဂဏန်းတွေအဖြစ် ဖတ်ရမယ်လို့ ဆိုလိုတယ်။ ဂဏန်းအတွက် code တွေက a ကနေ j အထိ အက္ခရာ code တွေနဲ့ အတူတူပဲ။

လိုက်ရေတွက်လာခဲ့တယ်ဆိုရင် အများဆုံး ၆၄ ပြည့်ဖို့ code ၇ မျိုး လိုသေးတယ်။ ဒီမှာ အဲဒီ ၇ မျိုးကို ပြထားတယ်။

![C.O.D.E အခန်း ၃ — လိုက်ရေတွက်လာခဲ့တယ်ဆိုရင် အများဆုံး ၆၄ ပြည့်ဖို့ code ၇ မျိုး လိုသေးတယ်။ ဒီမှာ အဲဒီ ၇ မျိုးကို ပြထားတယ်။](/images/blog/code-chapter-3/image15.jpg)

ပထမဆုံး code—ဖောင်းကြွအစက် ၄—ကို accent indicator အဖြစ် သုံးတယ်။ ကျန် code တွေကို အတိုကောက်တချို့ရဲ့ prefix အဖြစ်နဲ့ တခြားရည်ရွယ်ချက်တချို့အတွက် သုံးတယ်။ အစက် ၄ နဲ့ ၆ ဖောင်းနေတဲ့ code—ဒီတန်းထဲက ပဉ္စမ code—ဟာ အကြောင်းအရာပေါ်မူတည်ပြီး ဂဏန်းရဲ့ decimal point ဒါမှမဟုတ် အလေးပေးဖော်ပြချက် indicator ဖြစ်တယ်။ အစက် ၅ နဲ့ ၆ ဖောင်းနေတဲ့ ဆဋ္ဌမ code ကတော့ number indicator ရဲ့ အာနိသင်ကို ပြန်ဖျက်ပေးတဲ့ letter indicator ဖြစ်တယ်။

နောက်ဆုံးအနေနဲ့—Braille မှာ အက္ခရာအကြီးတွေကို ဘယ်လို encode လုပ်သလဲလို့ စဉ်းစားနေခဲ့ရင်—အစက် ၆ ရှိတယ်။ ဒါက capital indicator ဖြစ်ပြီး နောက်ကလာတဲ့ အက္ခရာကို uppercase အဖြစ် ဖတ်ရမယ်လို့ ဆိုလိုတယ်။ ဥပမာ ဒီစနစ်ရဲ့ မူလတီထွင်သူနာမည်ကို အောက်ပါအတိုင်း ရေးနိုင်တယ်။

![C.O.D.E အခန်း ၃ — နောက်ဆုံးအနေနဲ့—Braille မှာ အက္ခရာအကြီးတွေကို ဘယ်လို encode လုပ်သလဲလို့ စဉ်းစားနေခဲ့ရင်—အစက် ၆ ရှိတယ်။ ဒါက cap](/images/blog/code-chapter-3/image16.jpg)

ဒီအစီအစဉ်ဟာ capital indicator နဲ့စပြီး နောက်မှာ l၊ ou အတိုကောက်၊ i နဲ့ s၊ space တစ်ခု၊ နောက်ထပ် capital indicator တစ်ခု၊ ပြီးတော့ b၊ r၊ a၊ i၊ l၊ l နဲ့ e တို့ လိုက်လာတယ်။ (တကယ်သုံးတဲ့အခါ အသံမထွက်တဲ့ နောက်ဆုံးအက္ခရာနှစ်လုံးကို ဖြုတ်ပြီး ပိုတိုအောင်ရေးနိုင်သလို “brl” လို့လည်း ရေးနိုင်တယ်။)

အကျဉ်းချုပ်ရရင် binary အစိတ်အပိုင်း ၆ ခု—အစက် ၆ ခု—က ဖြစ်နိုင်တဲ့ code ၆၄ မျိုးတိတိကို ပေးနိုင်ပြီး ဒီထက်မပိုနိုင်ဘူးဆိုတာ တွေ့ခဲ့ပြီ။ ဒီ code ၆၄ မျိုးထဲက အများအပြားဟာ အကြောင်းအရာပေါ်မူတည်ပြီး တာဝန်နှစ်မျိုး ထမ်းဆောင်နေတယ်။ အထူးစိတ်ဝင်စားစရာက number indicator နဲ့ သူ့အာနိသင်ကို ပြန်ဖျက်ပေးတဲ့ letter indicator ပဲ။ ဒီ code တွေက နောက်ကလိုက်လာတဲ့ code တွေရဲ့ အဓိပ္ပာယ်ကို အက္ခရာကနေ ဂဏန်းအဖြစ်၊ ဂဏန်းကနေ အက္ခရာအဖြစ် ပြောင်းပေးတယ်။ ဒီလို code မျိုးကို precedence code ဒါမှမဟုတ် shift code လို့ ခေါ်လေ့ရှိတယ်။ Shift ကို ပြန်မဖျက်မချင်း နောက်က code အားလုံးရဲ့ အဓိပ္ပာယ်ကို ပြောင်းထားပေးတယ်။

Shift code ဟာ computer keyboard ပေါ်က Shift key ကို ဖိထားတာနဲ့ ဆင်တူတယ်။ Shift လို့နာမည်ပေးထားတာက လက်နှိပ်စက်အဟောင်းတွေမှာ uppercase အက္ခရာရိုက်ဖို့ သက်ဆိုင်ရာ key က စက်ပိုင်းဆိုင်ရာယန္တရားကို တကယ်ရွှေ့ပေးခဲ့လို့ပဲ။

Braille ရဲ့ capital indicator က နောက်ကအက္ခရာတစ်လုံးတည်းကိုသာ lowercase မဟုတ်ဘဲ uppercase အဖြစ် ဖတ်ရမယ်လို့ ဆိုလိုတယ်။ ဒီလို code မျိုးကို escape code လို့ ခေါ်တယ်။ Escape code က code တစ်ခုရဲ့ ပုံမှန်အဓိပ္ပာယ်ကနေ “လွတ်ထွက်” ပြီး တခြားနည်းနဲ့ အဓိပ္ပာယ်ဖတ်နိုင်အောင် လုပ်ပေးတယ်။ စာအရေးအသားတွေကို binary code နဲ့ ကိုယ်စားပြုတဲ့အခါ shift code နဲ့ escape code တွေကို မကြာခဏ သုံးကြတယ်။ ဒါပေမယ့် သူတို့ကြောင့် ရှုပ်ထွေးမှုလည်း ဝင်လာနိုင်တယ်။ ရှေ့မှာ ဘယ် code တွေလာခဲ့သလဲဆိုတာ မသိဘဲ code တစ်ခုချင်းကို သူ့ဘာသာ အဓိပ္ပာယ်ဖတ်လို့ မရတော့ဘူး။

၁၈၅၅ ခုနှစ်လောက်ကတည်းက Braille ကို ထောက်ခံသူတချို့ဟာ အစက်နှစ်ခုပါတဲ့ နောက်ထပ်တစ်တန်း ပေါင်းပြီး စနစ်ကို ချဲ့ထွင်လာကြတယ်။ အစက် ၈ ခုပါတဲ့ Braille ကို ဂီတ၊ stenography နဲ့ ဂျပန် kanji အက္ခရာတွေလို အထူးရည်ရွယ်ချက်တချို့အတွက် သုံးခဲ့ကြတယ်။ ဖြစ်နိုင်တဲ့ ထူးခြား code အရေအတွက်ကို ၂⁸၊ ဒါမှမဟုတ် ၂၅၆ မျိုးအထိ တိုးစေလို့ computer application တချို့မှာလည်း အဆင်ပြေတယ်။ Lowercase နဲ့ uppercase အက္ခရာတွေ၊ ဂဏန်းတွေနဲ့ ပုဒ်ဖြတ်ပုဒ်ရပ်အားလုံးကို shift code နဲ့ escape code တွေရဲ့ အရှုပ်အရှင်းမလိုဘဲ ကိုယ်ပိုင် code တစ်ခုစီ ပေးနိုင်သွားတယ်။
