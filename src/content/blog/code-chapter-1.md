## အချစ်ဆုံး သူငယ်ချင်းများ

မင်းအသက် ၁၀ နှစ်လောက်ပဲရှိသေးတယ်ဆိုပါစို့။ မင်းရဲ့အချစ်ဆုံးသူငယ်ချင်းက လမ်းတစ်ဖက်ခြမ်းက အိမ်မှာနေတယ်။ နှစ်ယောက်စလုံးရဲ့ အိပ်ခန်းပြတင်းပေါက်တွေကလည်း တစ်ခုနဲ့တစ်ခု တကယ်ကို မျက်နှာချင်းဆိုင် ရှိနေတယ်။ ညတိုင်း မိဘတွေက ထုံးစံအတိုင်း အိပ်ရာဝင်ချိန်ရောက်ပြီလို့ မတရားအစောကြီး ပြောသွားတဲ့အချိန် မင်းတို့နှစ်ယောက်မှာ အတွေးတွေ၊ မြင်တွေ့သတိထားမိတာတွေ၊ လျှို့ဝှက်ချက်တွေ၊ အတင်းအဖျင်းတွေ၊ ဟာသတွေ၊ အိပ်မက်တွေ အပြန်အလှန်ပြောဖို့ ကျန်နေသေးတယ်။ ဒါကို ဘယ်သူက အပြစ်တင်နိုင်မှာလဲ။ တစ်ယောက်နဲ့တစ်ယောက် ဆက်သွယ်ချင်တဲ့ စိတ်ဆန္ဒဟာ လူသားတွေရဲ့ သဘာဝအကျဆုံး လက္ခဏာတွေထဲက တစ်ခုပဲလေ။

အိပ်ခန်းမီးတွေ ဖွင့်ထားတုန်းဆိုရင်တော့ ပြတင်းပေါက်ကနေ လက်လှမ်းပြလို့ရတယ်။ လက်အမူအရာကြီးကြီးတွေ၊ အခြေခံကျတဲ့ ကိုယ်ဟန်အမူအရာတွေ သုံးပြီး အတွေးတစ်ခုနှစ်ခုလောက်ကိုလည်း ပြောပြနိုင်မယ်။ ဒါပေမယ့် ဒီထက်အသေးစိတ်ကျတဲ့ စကားပြောဆိုမှုမျိုးဆို ခက်လာပြီ။ မိဘတွေက “မီးပိတ်တော့!” လို့ အမိန့်ချလိုက်ပြီဆိုရင်တော့ သူတို့မသိအောင် လုပ်နိုင်မယ့် နည်းလမ်းတစ်ခု လိုလာတယ်။

ဘယ်လိုဆက်သွယ်ကြမလဲ။ အသက် ၁၀ နှစ်နဲ့တင် cell phone တစ်လုံးရှိထားလောက်အောင် ကံကောင်းရင်တော့ ဖုန်းခိုးခေါ်တာဖြစ်ဖြစ်၊ အသံမထွက်အောင် စာပို့တာဖြစ်ဖြစ် အဆင်ပြေနိုင်တယ်။ ဒါပေမယ့် အိပ်ရာဝင်ချိန်ရောက်တိုင်း မိဘတွေက cell phone တွေကို သိမ်းတတ်ပြီး Wi-Fi ပါ ပိတ်တတ်ရင်ရော။ အီလက်ထရွန်နစ် ဆက်သွယ်ရေး ဘာတစ်ခုမှမရှိတဲ့ အိပ်ခန်းဟာ တကယ်ကို အထီးကျန်လွန်းတဲ့နေရာ ဖြစ်သွားမှာပဲ။

ဒါပေမယ့် မင်းတို့နှစ်ယောက်စလုံးမှာ ဓာတ်မီးတော့ ရှိတယ်။ ဓာတ်မီးကို စောင်ခြုံထဲမှာ စာအုပ်ခိုးဖတ်နိုင်အောင် ကလေးတွေအတွက် တီထွင်ထားတာဆိုတာ လူတိုင်းသိကြတာပဲ။ အမှောင်ကျပြီးမှ ဆက်သွယ်ဖို့ကလဲ ဓာတ်မီးက အသင့်တော်ဆုံးပဲလို့ ထင်ရတယ်။ ဘာအသံမှ မထွက်တဲ့အပြင် အလင်းကလည်း ဦးတည်ရာတစ်ခုတည်းကိုပဲ ထိုးလို့ရတော့ သံသယများနေတဲ့ မိဘတွေ သတိထားမိလောက်အောင် အလင်းရောင်တွေက အိပ်ခန်းတံခါးအောက်ကနေ လျှံထွက်သွားဖို့လည်း မရှိသလောက်ပဲ။

ဒါဆို ဓာတ်မီးကို စကားပြောခိုင်းလို့ရမလား။ စမ်းကြည့်ရကျိုးတော့ နပ်မှာသေချာတယ်။ ပထမတန်းကတည်းက စာရွက်ပေါ်မှာ အက္ခရာတွေ၊ စကားလုံးတွေ ရေးတတ်ခဲ့ပြီဆိုတော့ အဲဒီအသိကို ဓာတ်မီးနဲ့ အသုံးချလို့ရမယ်ထင်တာ မဆန်းပါဘူး။ ပြတင်းပေါက်နားမှာရပ်ပြီး အလင်းနဲ့ အက္ခရာပုံဖော်လိုက်ရုံပဲ။ O ရေးမယ်ဆို ဓာတ်မီးဖွင့်၊ လေထဲမှာ အဝိုင်းတစ်ပတ် ဆွဲပြီး ဓာတ်မီးပိတ်။ I ဆိုရင်တော့ ဒေါင်လိုက်မျဉ်းတစ်ကြောင်း ဆွဲလိုက်မယ်။ ဒါပေမယ့် သိပ်မကြာခင်မှာပဲ ဒီနည်းက လုံးဝအလုပ်မဖြစ်ဘူးဆိုတာ သိလာတယ်။ သူငယ်ချင်းရဲ့ ဓာတ်မီးက လေထဲမှာ မျဉ်းကွေးတွေ၊ မျဉ်းတန်းတွေ လှုပ်ရှားဆွဲနေတာကို ကြည့်ရင်း မျဉ်းတိုင်းကို စိတ်ထဲမှာ ပြန်ဆက်ပြီး အက္ခရာတစ်လုံးဖြစ်အောင် လုပ်ဖို့က ခက်လွန်းနေတယ်။ လင်းခနဲပေါ်လာတဲ့ အဝိုင်းအကွေးတွေ၊ မျဉ်းစောင်းတွေဟာလည်း တိကျမှု မရှိဘူး။

ပင်လယ်ပြင်တစ်ဖက်နဲ့တစ်ဖက် သင်္ဘောသားနှစ်ယောက် မီးအဖွင့်အပိတ်လုပ်ပြီး အချက်ပြကြတဲ့ ရုပ်ရှင်မျိုး မင်းကြည့်ဖူးချင်ကြည့်ဖူးမယ်။ တခြားရုပ်ရှင်တစ်ကားမှာတော့ သူလျှိုတစ်ယောက်က မှန်ကို လှုပ်ပြီး နေရောင်ပြန်ဟပ်စေကာ အခန်းတစ်ခန်းထဲမှာ အကျဉ်းကျနေတဲ့ နောက်သူလျှိုတစ်ယောက်ဆီ အချက်ပြတာမျိုးလည်း ရှိနိုင်တယ်။ ဖြေရှင်းနည်းက ဒါများလား။ ဒါနဲ့ ရိုးရိုးလေး နည်းတစ်ခု အရင်စဉ်းစားတယ်။ အက္ခရာတစ်လုံးစီကို ဓာတ်မီးအချက်ပြ အရေအတွက်တစ်ခုစီနဲ့ တွဲထားမယ်။ A ဆို ၁ ချက်၊ B ဆို ၂ ချက်၊ C ဆို ၃ ချက်၊ ဒီလိုနဲ့ Z ဆို ၂၆ ချက်အထိပေါ့။ BAD ဆိုတဲ့ စကားလုံးကို အချက် ၂ ချက်၊ ၁ ချက်၊ ၄ ချက် လင်းပြမယ်။ အက္ခရာတစ်လုံးနဲ့တစ်လုံးကြား ခဏနားမယ်။ မနားရင် စုစုပေါင်း ၇ ချက်ကို G လို့ မှားသွားနိုင်တယ်။ စကားလုံးတစ်လုံးနဲ့တစ်လုံးကြားမှာတော့ ဒီထက်နည်းနည်းပိုကြာအောင် နားမယ်။

ဒီနည်းက အလားအလာရှိသလိုပဲ။ ကောင်းတဲ့အချက်က ဓာတ်မီးကို လေထဲမှာ ဝှေ့ယမ်းနေစရာ မလိုတော့ဘူး။ ဦးတည်ရာကို ချိန်ပြီး ခလုတ်နှိပ်ရုံပဲ။ မကောင်းတာက ပထမဆုံး ပို့ကြည့်တဲ့ စာတွေထဲက “How are you?” ဆိုတဲ့ စာတစ်ကြောင်းတည်းကိုပင် စုစုပေါင်း မီး ၁၃၁ ချက်တိတိ လင်းပြရတာပဲ။ နောက်ပြီး ပုဒ်ဖြတ်ပုဒ်ရပ်တွေကို ထည့်မစဉ်းစားမိထားတော့ မေးခွန်းအမှတ်အသား (?) အတွက် ဘယ်နှချက်လင်းရမလဲဆိုတာလည်း မသိဘူး။

ဒါပေမယ့် အဖြေနားကိုတော့ ရောက်နေပြီ။ ဒီပြဿနာမျိုးကို အရင်က တစ်ယောက်ယောက် ကြုံဖူးမှာပဲလို့ တွေးမိတယ်မဟုတ်လား။ တွေးတာ လုံးဝမှန်တယ်။ စာကြည့်တိုက်သွားရှာလိုက်တာပဲဖြစ်ဖြစ်၊ အင်တာနက်မှာ ရှာလိုက်တာပဲဖြစ်ဖြစ် Morse code ဆိုတဲ့ အံ့ဩစရာ တီထွင်မှုတစ်ခုကို တွေ့လာမယ်။ အက္ခရာအားလုံးကို “ရေး” နည်း အသစ်ပြန်ကျက်ရတော့မယ်ဆိုပေမယ့် ဒါက မင်းတို့ရှာနေတဲ့အရာ အတိအကျပဲ။

ကွာခြားချက်က ဒီလိုပါ။ မင်းတို့တီထွင်ထားတဲ့ စနစ်မှာ အက္ခရာတစ်လုံးစီဟာ အချက်ပြအရေအတွက်တစ်ခုစီနဲ့ ကိုက်ညီတယ်—A အတွက် ၁ ချက်ကနေ Z အတွက် ၂၆ ချက်အထိပေါ့။ Morse code မှာတော့ အချက်ပြတာ နှစ်မျိုးရှိတယ်—တိုတိုလင်းတာနဲ့ ကြာကြာလင်းတာ။ ဒါကြောင့် Morse code က ပိုရှုပ်သွားတာတော့ မှန်တယ်။ ဒါပေမယ့် တကယ်သုံးတဲ့အခါ အများကြီးပိုထိရောက်တယ်။ “How are you?” ဆိုတဲ့ စာကြောင်းကို အခု မီး ၃၂ ချက်ပဲ လင်းဖို့လိုတော့တယ်။ တချို့က တိုတို၊ တချို့က ရှည်ရှည်ဖြစ်ပြီး မေးခွန်းအမှတ်အသား (?) အတွက် code ပါ ထည့်တွက်ပြီးသား။ အရင်က ၁၃၁ ချက်လိုခဲ့တာနဲ့ယှဉ်ရင် တော်တော်ကွာတယ်။

Morse code အလုပ်လုပ်ပုံကို ပြောကြတဲ့အခါ လူတွေက “တိုတိုလင်းတာ” နဲ့ “ကြာကြာလင်းတာ” လို့ မခေါ်ကြဘူး။ စာမျက်နှာပေါ်မှာ code တွေကို ဖော်ပြရ လွယ်ကူအောင် “dot” နဲ့ “dash” လို့ပဲ ခေါ်ကြတယ်။ Morse code မှာ အက္ခရာတစ်လုံးစီကို dot နဲ့ dash အနည်းငယ်စီ စီစဉ်ပေါင်းထားတဲ့ code တစ်ခုစီနဲ့ သတ်မှတ်ထားတယ်။ အောက်ကဇယားမှာ ကြည့်နိုင်တယ်။

Morse code နဲ့ computer တွေဟာ လုံးဝ ဘာမှမဆိုင်ပေမယ့် code ဆိုတာ ဘယ်လိုသဘောမျိုးလဲဆိုတာ အရင်ရင်းနှီးထားဖို့ အလွန်အရေးကြီးတယ်။ ဒါက computer hardware နဲ့ software အတွင်းမှာ ဖုံးကွယ်နေတဲ့ ဘာသာစကားတွေနဲ့ အတွင်းပိုင်းဖွဲ့စည်းပုံတွေကို နက်နက်ရှိုင်းရှိုင်း နားလည်နိုင်ဖို့ မဖြစ်မနေလိုအပ်တဲ့ အခြေခံအဆင့်တစ်ခုပဲ။

ဒီစာအုပ်မှာ code ဆိုတဲ့ စကားလုံးကို အများအားဖြင့် လူတစ်ယောက်နဲ့တစ်ယောက်ကြား၊ လူနဲ့ computer ကြား၊ ဒါမှမဟုတ် computer တစ်လုံးရဲ့ အတွင်းပိုင်းမှာ သတင်းအချက်အလက် လွှဲပြောင်းပေးတဲ့ စနစ်တစ်ခုဆိုတဲ့ အဓိပ္ပာယ်နဲ့ သုံးထားတယ်။

Code တစ်ခုရှိရင် အချင်းချင်း ဆက်သွယ်နိုင်တယ်။ တချို့ code တွေက လျှို့ဝှက်ထားတာမှန်ပေမယ့် အများစုကတော့ လျှို့ဝှက်မဟုတ်ဘူး။ တကယ်တော့ code အများစုကို လူတွေ ကောင်းကောင်းနားလည်ထားမှသာ ဖြစ်မယ်။ ဘာလို့လဲဆိုတော့ လူအချင်းချင်း ဆက်သွယ်မှုက အဲဒီ code တွေပေါ်မှာ အခြေခံထားလို့ပဲ။

စကားလုံးတွေ ဖြစ်လာအောင် ပါးစပ်ကနေ ထုတ်တဲ့အသံတွေလည်း code တစ်မျိုးပါပဲ။ ကိုယ့်အသံကို ကြားနိုင်ပြီး ကိုယ်ပြောတဲ့ဘာသာစကားကို နားလည်သူတိုင်း ဒီ code ကို သဘောပေါက်နိုင်တယ်။ ဒီ code ကို “ပြောစကား” ဒါမှမဟုတ် “စကားပြောခြင်း” လို့ ခေါ်ကြတယ်။

နားမကြားသူအသိုင်းအဝိုင်းတွေမှာ လက်နဲ့ လက်မောင်းကို လှုပ်ရှားပြီး အမူအရာတွေ ဖန်တီးတဲ့ လက်သင်္ကေတဘာသာစကား အမျိုးမျိုးကို သုံးကြတယ်။ အဲဒီအမူအရာတွေက စကားလုံးထဲက အက္ခရာတစ်လုံးချင်းကိုဖြစ်စေ၊ စကားလုံးတစ်လုံးလုံးနဲ့ အယူအဆတစ်ခုလုံးကိုဖြစ်စေ ဖော်ပြနိုင်တယ်။ မြောက်အမေရိကမှာ အများဆုံးသုံးကြတဲ့ စနစ်နှစ်မျိုးကတော့ American Sign Language (ASL) နဲ့ Langue des signes Québécoise (LSQ) တို့ပဲ။ ASL ကို ၁၉ ရာစုအစောပိုင်းက American School for the Deaf မှာ ဖွံ့ဖြိုးတည်ဆောက်ခဲ့ပြီး LSQ ကတော့ ပြင်သစ်လက်သင်္ကေတဘာသာစကားရဲ့ မူကွဲတစ်မျိုး ဖြစ်တယ်။

စကားလုံးတွေကို စာရွက်ပေါ် ဒါမှမဟုတ် တခြားကြားခံတစ်ခုခုပေါ် တင်ဖို့ဆိုရင် “စာအရေးအသား” ဒါမှမဟုတ် “စာသား” လို့ခေါ်တဲ့ တခြား code တစ်မျိုးကို သုံးကြတယ်။ စာကို လက်နဲ့ရေးနိုင်သလို keyboard နဲ့လည်း ရိုက်နိုင်တယ်။ ပြီးရင် သတင်းစာ၊ မဂ္ဂဇင်း၊ စာအုပ်တွေထဲမှာ ပုံနှိပ်လို့ရသလို စက်အမျိုးမျိုးရဲ့ screen ပေါ်မှာလည်း ပြနိုင်တယ်။ ဘာသာစကားအတော်များများမှာ ပြောစကားနဲ့ စာသားကြား အနီးကပ်ဆက်စပ်မှုရှိတယ်။ ဥပမာ English မှာဆို အက္ခရာတစ်လုံးချင်းနဲ့ အက္ခရာအစုတွေက စကားပြောသံတွေနဲ့ အနည်းနဲ့အများ ကိုက်ညီနေတယ်။

အမြင်အာရုံချို့တဲ့သူတွေအတွက် စာအရေးအသားအစား Braille ကို သုံးနိုင်တယ်။ Braille မှာ ဖုထွက်နေတဲ့ အစက်တွေကို အက္ခရာတစ်လုံးချင်း၊ အက္ခရာအစုတွေ၊ စကားလုံးတစ်လုံးလုံးတို့နဲ့ ကိုက်ညီအောင် စနစ်တကျ သတ်မှတ်ထားတယ်။ (Braille အကြောင်းကို အခန်း ၃ မှာ ပိုအသေးစိတ် ပြောမယ်။)

ပြောသမျှစကားကို စာသားအဖြစ် အလွန်မြန်မြန် ကူးရေးဖို့လိုတဲ့အခါ stenography ဒါမှမဟုတ် shorthand က အသုံးဝင်တယ်။ တရားရုံးတွေမှာဖြစ်စေ၊ ရုပ်မြင်သံကြားသတင်းနဲ့ အားကစားအစီအစဉ်တွေအတွက် အချိန်နဲ့တစ်ပြေးညီ စာတန်းထိုးပေးရာမှာဖြစ်စေ stenographer တွေက stenotype machine ကို သုံးကြတယ်။ ဒီစက်မှာ ရိုးရှင်းအောင်လုပ်ထားတဲ့ keyboard တစ်ခုပါပြီး စာသားနဲ့ ကိုက်ညီတဲ့ ကိုယ်ပိုင် code စနစ်လည်း ရှိတယ်။

လူအချင်းချင်း ဆက်သွယ်ဖို့ code အမျိုးမျိုး သုံးကြတာက တချို့ code တွေဟာ တခြား code တွေထက် အခြေအနေတစ်ခုခုမှာ ပိုအဆင်ပြေလို့ပါ။ ပြောစကားကို စာရွက်ပေါ်မှာ သိမ်းထားလို့မရတဲ့အတွက် စာအရေးအသား code ကို အစားထိုးသုံးတယ်။ အမှောင်ထဲမှာ အဝေးကနေ အသံမထွက်ဘဲ သတင်းပို့ချင်ရင်တော့ စကားပြောလို့လည်းမရ၊ စာရွက်နဲ့လည်း အဆင်မပြေဘူး။ အဲဒီအခါ Morse code က အသုံးတည့်တဲ့ ရွေးချယ်စရာဖြစ်လာတယ်။ တခြားဘယ် code မှ မလုပ်ပေးနိုင်တဲ့ အလုပ်တစ်ခုကို လုပ်ပေးနိုင်ရင် အဲဒီ code က အသုံးဝင်တာပဲ။

ဆက်ပြီးမြင်တွေ့ရမယ့်အတိုင်း computer တွေထဲမှာလည်း စာသား၊ ဂဏန်း၊ အသံ၊ ဂီတ၊ ရုပ်ပုံနဲ့ ရုပ်ရှင်တွေကို သိမ်းဆည်းဖို့၊ လွှဲပြောင်းဖို့ code အမျိုးမျိုးကို သုံးကြတယ်။ Computer ကိုယ်တိုင် လိုက်နာရတဲ့ ညွှန်ကြားချက်တွေကိုလည်း code နဲ့ပဲ ကိုယ်စားပြုထားတယ်။ Computer တွေအတွက် လူသားတွေရဲ့ code ကို ကိုင်တွယ်ဖို့ မလွယ်ဘူး။ အကြောင်းက computer တွေဟာ လူတွေက မျက်စိ၊ နား၊ ပါးစပ်နဲ့ လက်ချောင်းတွေကို အသုံးပြုပုံအတိုင်း တိတိကျကျ လိုက်တုပလို့မရလို့ပဲ။ Computer ကို စကားပြောတတ်အောင် သင်ပေးရတာ ခက်တယ်။ လူပြောသမျှ နားလည်အောင် သင်ပေးရတာက ပိုတောင်ခက်သေးတယ်။

ဒါပေမယ့် တိုးတက်မှုတွေ အများကြီးတော့ ရှိလာပြီ။ အခုဆို computer တွေက လူအချင်းချင်း ဆက်သွယ်ရာမှာ သုံးတဲ့ သတင်းအချက်အလက် အမျိုးအစားအတော်များများကို ဖမ်းယူ၊ သိမ်းဆည်း၊ ပြုပြင်၊ ပြန်လည်ဖော်ပြနိုင်လာပြီ။ မျက်စိနဲ့မြင်ရတာတွေ—စာသားနဲ့ ရုပ်ပုံ၊ နားနဲ့ကြားရတာတွေ—ပြောစကား၊ အသံနဲ့ ဂီတ၊ ဒါမှမဟုတ် နှစ်မျိုးလုံးပေါင်းထားတာတွေ—animation နဲ့ ရုပ်ရှင် စတာတွေပေါ့။ ဒီသတင်းအချက်အလက် အမျိုးအစားတစ်ခုစီအတွက် ကိုယ်ပိုင် code လိုအပ်တယ်။

အခုလေးတင် ကြည့်ခဲ့တဲ့ Morse code ဇယားကိုယ်တိုင်တောင် code တစ်မျိုးလို့ ဆိုနိုင်တယ်။ အဲဒီဇယားက အက္ခရာတစ်လုံးစီကို dot နဲ့ dash အစီအစဉ်တစ်ခုစီနဲ့ ကိုယ်စားပြုထားကြောင်း ပြတယ်။ ဒါပေမယ့် dot တွေ၊ dash တွေကို တကယ်တမ်း ပို့လို့တော့မရဘူး။ ဓာတ်မီးနဲ့ Morse code ပို့တဲ့အခါ အဲဒီ dot နဲ့ dash တွေကို မီးလင်းတဲ့အချက်တွေနဲ့ ကိုယ်စားပြုရတယ်။

ဓာတ်မီးနဲ့ Morse code ပို့မယ်ဆိုရင် dot အတွက် ဓာတ်မီးခလုတ်ကို မြန်မြန်ဖွင့်ပြီး ပြန်ပိတ်ရတယ်။ Dash အတွက်တော့ နည်းနည်းပိုကြာအောင် ဖွင့်ထားရတယ်။ ဥပမာ A ပို့ချင်ရင် ဓာတ်မီးကို မြန်မြန်ဖွင့်ပိတ်တစ်ခါလုပ်၊ ပြီးတော့ အရင်တစ်ခါလောက် မမြန်ဘဲ ဖွင့်ပိတ်တစ်ခါ ထပ်လုပ်ပြီး နောက်အက္ခရာမစခင် ခဏနားရမယ်။ သတ်မှတ်ထားတဲ့ ထုံးစံအရ dash တစ်ခုရဲ့ ကြာချိန်ဟာ dot တစ်ခုထက် သုံးဆလောက် ရှည်သင့်တယ်။ လက်ခံသူက မီးတိုတစ်ချက်နဲ့ မီးရှည်တစ်ချက်ကို မြင်တာနဲ့ A လို့ သိသွားမယ်။

Morse code ထဲမှာ dot နဲ့ dash ကြားက နားချိန်တွေက အလွန်အရေးကြီးတယ်။ ဥပမာ A ပို့တဲ့အခါ dot နဲ့ dash ကြားမှာ ဓာတ်မီးပိတ်ထားရမယ့်အချိန်ဟာ dot တစ်ခုစာကြာချိန်လောက် ရှိသင့်တယ်။ စကားလုံးတစ်လုံးတည်းထဲက အက္ခရာတွေကြားမှာတော့ dash တစ်ခုစာလောက် ပိုကြာကြာ နားရတယ်။ အက္ခရာတွေကြားက နားချိန်တွေပါ မြင်ရအောင် “hello” ရဲ့ Morse code ကို အောက်မှာ ပြထားတယ်။

စကားလုံးတစ်လုံးနဲ့တစ်လုံးကြားမှာတော့ dash နှစ်ခုစာလောက် မီးပိတ်ပြီး နားရတယ်။ “hi there” အတွက် code က ဒီလိုပါ။

ဓာတ်မီးကို ဖွင့်ထားချိန်၊ ပိတ်ထားချိန်တွေရဲ့ အရှည်ကို ပုံသေသတ်မှတ်ထားတာ မဟုတ်ဘူး။ အချိန်အားလုံးကို dot တစ်ခုရဲ့ ကြာချိန်နဲ့ နှိုင်းယှဉ်ပြီး သတ်မှတ်တယ်။ Dot တစ်ခု ဘယ်လောက်ကြာမလဲဆိုတာက ဓာတ်မီးခလုတ်ကို ဘယ်လောက်မြန်မြန် နှိပ်နိုင်သလဲ၊ စာပို့သူက အက္ခရာတစ်လုံးရဲ့ Morse code ကို ဘယ်လောက်မြန်မြန် ပြန်မှတ်မိသလဲဆိုတာပေါ် မူတည်တယ်။ မြန်တဲ့သူရဲ့ dash တစ်ခုက နှေးတဲ့သူရဲ့ dot တစ်ခုနဲ့ ကြာချိန်တူနေနိုင်တယ်။ ဒီပြဿနာသေးသေးလေးကြောင့် Morse code စာတစ်စောင်ကို ဖတ်ရခက်သွားနိုင်ပေမယ့် အက္ခရာတစ်လုံးနှစ်လုံးလောက် လက်ခံပြီးရင် ဘယ်ဟာ dot၊ ဘယ်ဟာ dash ဆိုတာကို လက်ခံသူက များသောအားဖြင့် ခွဲသိနိုင်တယ်။

ပထမဆုံးကြည့်လိုက်ရင် Morse code ရဲ့ သတ်မှတ်ပုံ—ဒီနေရာမှာ သတ်မှတ်ပုံဆိုတာ dot နဲ့ dash အစီအစဉ်မျိုးစုံကို အက္ခရာတွေနဲ့ ကိုက်ညီအောင် တွဲထားပုံကို ဆိုလိုတာ— computer keyboard ပေါ်က အက္ခရာနေရာချထားပုံလိုပဲ စည်းကမ်းမရှိ၊ ကျပန်းဖြစ်နေသလို ထင်ရတယ်။ ဒါပေမယ့် အသေအချာကြည့်လိုက်ရင်တော့ လုံးဝကျပန်း မဟုတ်ဘူး။ E နဲ့ T လို မကြာခဏအသုံးများတဲ့ အက္ခရာတွေကို ပိုရိုးရှင်းပြီး ပိုတိုတဲ့ code တွေ ပေးထားတယ်။ Scrabble ကစားသူတွေနဲ့ Wheel of Fortune ပရိသတ်တွေဆို ဒါကို ချက်ချင်းသတိထားမိနိုင်တယ်။ Q နဲ့ Z လို သုံးခဲတဲ့ အက္ခရာတွေ—Scrabble မှာ ၁၀ မှတ်ရပြီး Wheel of Fortune စကားလုံးပဟေဠိတွေထဲမှာလည်း တွေ့ရခဲတဲ့ အက္ခရာတွေ—ကိုတော့ ပိုရှည်တဲ့ code တွေ သတ်မှတ်ထားတယ်။

လူတိုင်းနီးပါး Morse code နည်းနည်းတော့ သိကြတယ်။ Dot သုံးခု၊ dash သုံးခု၊ dot သုံးခုက နိုင်ငံတကာ အရေးပေါ်အကူအညီတောင်းတဲ့ အချက်ပြ SOS ကို ကိုယ်စားပြုတယ်။ SOS ဟာ ဘယ်စကားစုရဲ့ အတိုကောက်မှ မဟုတ်ဘူး။ မှတ်ရလွယ်တဲ့ Morse code အစီအစဉ်တစ်ခု သက်သက်ပဲ။ ဒုတိယကမ္ဘာစစ်အတွင်း British Broadcasting Corporation က ရေဒီယိုအစီအစဉ်တချို့ကို Beethoven ရဲ့ ပဉ္စမမြောက် symphony အစပိုင်း—BAH, BAH, BAH, BAHMMMMM—နဲ့ စခဲ့တယ်။ Beethoven က ဒီတေးကိုရေးခဲ့စဉ်တုန်းကတော့ တစ်နေ့မှာ ဒါဟာ Victory ရဲ့ V အတွက် Morse code ဖြစ်လာမယ်ဆိုတာ ဘယ်သိခဲ့မှာလဲ။

Morse code ရဲ့ အားနည်းချက်တစ်ခုက အက္ခရာအကြီးနဲ့ အက္ခရာအသေးကို ခွဲမပြနိုင်တာပဲ။ ဒါပေမယ့် အက္ခရာတွေအပြင် ဂဏန်းတွေအတွက်လည်း code ရှိတယ်။ ဂဏန်းတစ်လုံးစီကို dot နဲ့ dash ငါးခု စီထားတဲ့ အစီအစဉ်တစ်ခုနဲ့ ဖော်ပြတယ်။

![Morse code ဂဏန်း ၀ မှ ၉ အထိ ဇယား](/images/blog/code-chapter-1/morse-numbers.jpg)

အနည်းဆုံးတော့ ဒီဂဏန်း code တွေက အက္ခရာ code တွေထက် စနစ်နည်းနည်းကျတယ်။ ပုဒ်ဖြတ်ပုဒ်ရပ်အများစုအတွက်တော့ dot နဲ့ dash ငါးခု၊ ခြောက်ခု ဒါမှမဟုတ် ခုနစ်ခု သုံးထားတယ်။

![Morse code ပုဒ်ဖြတ်ပုဒ်ရပ် သင်္ကေတ ဇယား](/images/blog/code-chapter-1/morse-punctuation.jpg)

ဥရောပဘာသာစကားတချို့က accent ပါတဲ့ အက္ခရာတွေအတွက်လည်း code ထပ်သတ်မှတ်ထားတယ်။ အထူးရည်ရွယ်ချက်တွေအတွက် shorthand အစီအစဉ်တွေလည်း ရှိတယ်။ SOS က အဲဒီလို shorthand အစီအစဉ်တစ်မျိုးပဲ။ SOS ပို့တဲ့အခါ အက္ခရာသုံးလုံးကြားမှာ dot တစ်ခုစာသာ နားပြီး အဆက်မပြတ် ပို့ရတယ်။

မင်းနဲ့ မင်းသူငယ်ချင်းမှာ ဒီအလုပ်အတွက် အထူးလုပ်ထားတဲ့ ဓာတ်မီးမျိုးရှိရင် Morse code ပို့ရတာ ပိုလွယ်လာမယ်။ ဒီဓာတ်မီးတွေမှာ ပုံမှန် အဖွင့်အပိတ် slider switch အပြင် လက်နဲ့ဖိလိုက်တာနဲ့ မီးပွင့်ပြီး လွှတ်လိုက်တာနဲ့ ပိတ်သွားတဲ့ pushbutton switch တစ်ခုလည်း ပါတယ်။ လေ့ကျင့်ထားရင် တစ်မိနစ်ကို စကားလုံး ၅ လုံး၊ ၁၀ လုံးလောက်အထိ ပို့နိုင်၊ လက်ခံနိုင်လာမယ်။ စကားပြောနှုန်းက တစ်မိနစ်ကို စကားလုံး ၁၀၀ ဝန်းကျင်ရှိလို့ အများကြီးပိုနှေးနေသေးပေမယ့် မင်းတို့အတွက်တော့ လုံလောက်မှာ သေချာပါတယ်။

နောက်ဆုံး မင်းနဲ့ မင်းရဲ့အချစ်ဆုံးသူငယ်ချင်းတို့ Morse code ကို အလွတ်ရသွားတဲ့အခါ—ကျွမ်းကျွမ်းကျင်ကျင် ပို့တတ်၊ လက်ခံတတ်ချင်ရင် အလွတ်ကျက်တာကလွဲပြီး နည်းမရှိဘူး—ပုံမှန်စကားပြောမယ့်အစား Morse code ကို အသံနဲ့လည်း သုံးနိုင်တယ်။ မြန်နိုင်သမျှ မြန်အောင် dot ကို dih လို့ အသံထွက်တယ်။ အက္ခရာတစ်လုံးရဲ့ နောက်ဆုံး dot ဆိုရင် dit လို့ထွက်ပြီး dash ကိုတော့ dah လို့ ထွက်တယ်။ ဥပမာ V ဆိုရင် dih-dih-dih-dah လို့ အသံထွက်မယ်။ Morse code က စာအရေးအသားကို dot နဲ့ dash နှစ်မျိုးတည်းအဖြစ် ပြောင်းလိုက်သလိုပဲ၊ အသံနဲ့ပြောတဲ့ Morse code က စကားသံကို သရသံနှစ်မျိုးတည်းအဖြစ် ပြောင်းလိုက်တယ်။

ဒီနေရာမှာ အဓိကကျတဲ့ စကားလုံးက နှစ်မျိုး ဆိုတာပဲ။ မီးလင်းပုံနှစ်မျိုး၊ သရသံနှစ်မျိုး—တကယ်တော့ မတူတဲ့အရာ ဘာနှစ်မျိုးမဆို သင့်တော်အောင် တွဲစပ်လိုက်ရင် သတင်းအချက်အလက် အမျိုးမျိုးကို ဖော်ပြနိုင်တယ်။
