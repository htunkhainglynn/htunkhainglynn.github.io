## Code တွေနဲ့ ပေါင်းစပ်မှုတွေ

Morse code ကို ၁၈၃၇ ခုနှစ်ဝန်းကျင်မှာ Samuel Finley Breese Morse (၁၇၉၁–၁၈၇၂) က တီထွင်ခဲ့တယ်။ သူ့အကြောင်းကို ဒီစာအုပ်ရဲ့ နောက်ပိုင်းမှာ ပိုပြီးပြည့်ပြည့်စုံစုံ သိလာရမယ်။ အဲဒီနောက် တခြားသူတွေက ဆက်ပြီး ဖွံ့ဖြိုးအောင်လုပ်ခဲ့ကြပြီး အထူးသဖြင့် Alfred Vail (၁၈၀၇–၁၈၅၉) ရဲ့ ပါဝင်မှုက အရေးကြီးခဲ့တယ်။ ဒီလိုနဲ့ Morse code ဟာ မူကွဲနှစ်မျိုးလောက်အထိ ကွဲပြားလာခဲ့တယ်။ ဒီစာအုပ်မှာ ဖော်ပြထားတဲ့ စနစ်ကို တိတိကျကျခေါ်ရင် International Morse code လို့ခေါ်တယ်။

Morse code တီထွင်မှုနဲ့ telegraph တီထွင်မှုက တစ်ခုနဲ့တစ်ခု ခွဲလို့မရအောင် ဆက်စပ်နေတယ်။ Telegraph အကြောင်းကိုလည်း စာအုပ်နောက်ပိုင်းမှာ အသေးစိတ် ထပ်ကြည့်မယ်။ Morse code က code တွေရဲ့ သဘောသဘာဝကို စပြီးနားလည်ဖို့ ကောင်းတဲ့နမူနာတစ်ခု ဖြစ်သလို telegraph ထဲမှာလည်း computer အလုပ်လုပ်ပုံကို လိုက်တုပနိုင်တဲ့ hardware တွေ ပါဝင်တယ်။

လူအများစုအတွက် Morse code ကို လက်ခံဖတ်ရတာထက် ပို့ရတာ ပိုလွယ်တယ်။ Morse code ကို အလွတ်မရသေးရင်တောင် ပြီးခဲ့တဲ့အခန်းမှာ တွေ့ခဲ့တဲ့ အက္ခရာစဉ်အလိုက် စီထားတဲ့ ဒီဇယားကို ကြည့်ပြီး ပို့လို့ရတယ်။

![C.O.D.E အခန်း ၂ — လူအများစုအတွက် Morse code ကို လက်ခံဖတ်ရတာထက် ပို့ရတာ ပိုလွယ်တယ်။ Morse code ကို အလွတ်မရသေးရင်တောင် ပြီးခဲ့တဲ့အ](/images/blog/code-chapter-2/image1.jpg)

Morse code ကို လက်ခံပြီး စကားလုံးတွေအဖြစ် ပြန်ဖော်ရတာက ပို့ရတာထက် အများကြီးပိုခက်ပြီး အချိန်လည်းပိုယူတယ်။ အကြောင်းက dot နဲ့ dash အစီအစဉ်တစ်ခုကို မြင်ရင် ဘယ်အက္ခရာနဲ့ ကိုက်ညီသလဲဆိုတာ နောက်ပြန်ရှာရလို့ပဲ။ Code တွေကို အလွတ်မရဘဲ dash-dot-dash-dash ကို လက်ခံရပြီဆိုပါစို့။ အဲဒါ Y ဖြစ်ကြောင်း တွေ့တဲ့အထိ ဇယားထဲမှာ အက္ခရာတစ်လုံးချင်း လိုက်ရှာနေရမယ်။

ပြဿနာက လက်ရှိဇယားက အောက်ပါအတိုင်း ဘာသာပြန်ပေးနိုင်တာပဲ။

အက္ခရာ  →  Morse code ရဲ့ dot နှင့် dash များ

ဒါပေမယ့် ပြောင်းပြန်ရှာပေးနိုင်တဲ့ ဇယားတော့ မရှိသေးဘူး။

Morse code ရဲ့ dot နှင့် dash များ  →  အက္ခရာ

Morse code ကို စလေ့လာခါစမှာ ဒီလိုဇယားတစ်ခုရှိရင် တော်တော်အဆင်ပြေမှာ သေချာတယ်။ ဒါပေမယ့် ဘယ်လိုတည်ဆောက်ရမလဲဆိုတာ ရုတ်တရက်ကြည့်ရုံနဲ့ မသိသာဘူး။ Dot နဲ့ dash တွေထဲမှာ အက္ခရာစဉ်အလိုက် စီလို့ရမယ့်အရာ ဘာမှမရှိဘူး။

ဒါဆို အက္ခရာစဉ်ကို ခဏမေ့ထားလိုက်ကြစို့။ Code တစ်ခုမှာ dot နဲ့ dash ဘယ်နှခုပါသလဲဆိုတာအလိုက် အုပ်စုခွဲတာက ပိုကောင်းတဲ့နည်း ဖြစ်နိုင်တယ်။ ဥပမာ dot တစ်ခုတည်း ဒါမှမဟုတ် dash တစ်ခုတည်းပါတဲ့ Morse code အစီအစဉ်က E နဲ့ T ဆိုတဲ့ အက္ခရာနှစ်လုံးကိုပဲ ကိုယ်စားပြုနိုင်တယ်။

![C.O.D.E အခန်း ၂ — ဒါဆို အက္ခရာစဉ်ကို ခဏမေ့ထားလိုက်ကြစို့။ Code တစ်ခုမှာ dot နဲ့ dash ဘယ်နှခုပါသလဲဆိုတာအလိုက် အုပ်စုခွဲတာက ပိုကော](/images/blog/code-chapter-2/image2.jpg)

Dot ဒါမှမဟုတ် dash နှစ်ခုတိတိ ပေါင်းစပ်လိုက်ရင် I, A, N နဲ့ M ဆိုတဲ့ နောက်ထပ်အက္ခရာလေးလုံး ရလာတယ်။

![C.O.D.E အခန်း ၂ — Dot ဒါမှမဟုတ် dash နှစ်ခုတိတိ ပေါင်းစပ်လိုက်ရင် I, A, N နဲ့ M ဆိုတဲ့ နောက်ထပ်အက္ခရာလေးလုံး ရလာတယ်။](/images/blog/code-chapter-2/image3.jpg)

Dot နဲ့ dash သုံးခုစီထားတဲ့ ပုံစံတွေက နောက်ထပ်အက္ခရာရှစ်လုံး ပေးတယ်။

![C.O.D.E အခန်း ၂ — Dot နဲ့ dash သုံးခုစီထားတဲ့ ပုံစံတွေက နောက်ထပ်အက္ခရာရှစ်လုံး ပေးတယ်။](/images/blog/code-chapter-2/image4.jpg)

နောက်ဆုံးအနေနဲ့—ဂဏန်းတွေနဲ့ ပုဒ်ဖြတ်ပုဒ်ရပ်တွေ မရောက်ခင် ဒီလေ့ကျင့်ခန်းကို ရပ်မယ်ဆိုရင်—dot နဲ့ dash လေးခုစီထားတဲ့ အစီအစဉ်တွေက နောက်ထပ်စာလုံး ၁၆ လုံးကို ကိုယ်စားပြုနိုင်တယ်။

![C.O.D.E အခန်း ၂ — နောက်ဆုံးအနေနဲ့—ဂဏန်းတွေနဲ့ ပုဒ်ဖြတ်ပုဒ်ရပ်တွေ မရောက်ခင် ဒီလေ့ကျင့်ခန်းကို ရပ်မယ်ဆိုရင်—dot နဲ့ dash လေးခုစီထာ](/images/blog/code-chapter-2/image5.jpg)

ဒီဇယားလေးခုကို ပေါင်းလိုက်ရင် code အရေအတွက်က ၂ + ၄ + ၈ + ၁၆ ဖြစ်လို့ စုစုပေါင်း ၃၀ ရတယ်။ Latin အက္ခရာ ၂၆ လုံးအတွက် လိုတာထက် ၄ ခု ပိုနေတယ်။ ဒါကြောင့် နောက်ဆုံးဇယားထဲက code ၄ ခုဟာ accent ပါတဲ့ အက္ခရာတွေအတွက် ဖြစ်နေတာကို သတိထားမိလိမ့်မယ်။ သုံးလုံးမှာ umlaut ပါပြီး တစ်လုံးမှာ cedilla ပါတယ်။

တစ်ယောက်ယောက်က Morse code ပို့လာတဲ့အခါ ဒီဇယားလေးခုက တကယ်အကူအညီဖြစ်တယ်။ အက္ခရာတစ်လုံးအတွက် code တစ်ခု လက်ခံရပြီးတာနဲ့ dot နဲ့ dash ဘယ်နှခုပါသလဲဆိုတာ သိပြီဖြစ်လို့ သက်ဆိုင်ရာဇယားကို တန်းသွားရှာနိုင်တယ်။ ဇယားတစ်ခုစီမှာ ဘယ်ဘက်အပေါ်ဆုံးက dot တွေချည်းပါတဲ့ code နဲ့စပြီး ညာဘက်အောက်ဆုံးက dash တွေချည်းပါတဲ့ code အထိ စနစ်တကျ စီထားတယ်။

ဇယားလေးခုရဲ့ အရွယ်အစားမှာ ပုံစံတစ်ခု ထပ်နေတယ်ဆိုတာ မြင်မိလား။ ဇယားတစ်ခုစီမှာ အရင်ဇယားထက် code နှစ်ဆပါနေတယ်။ ဒါကလည်း အဓိပ္ပာယ်ရှိတယ်။ ဇယားအသစ်တစ်ခုမှာ အရင်ဇယားက code အားလုံးရဲ့ နောက်မှာ dot တစ်ခုစီ ထပ်ပေါင်းထားတဲ့ code တွေရှိသလို dash တစ်ခုစီ ထပ်ပေါင်းထားတဲ့ code တွေလည်း ရှိတယ်။

စိတ်ဝင်စားစရာကောင်းတဲ့ ဒီတိုးပွားပုံကို ဒီလိုအကျဉ်းချုပ် ပြနိုင်တယ်။

ဇယားတစ်ခုစီမှာ အရင်ဇယားထက် code နှစ်ဆပါနေတယ်။ ဒါကြောင့် ပထမဇယားမှာ code ၂ ခုရှိရင် ဒုတိယဇယားမှာ ၂ × ၂ ခု၊ တတိယဇယားမှာ ၂ × ၂ × ၂ ခု ရှိမယ်။ နောက်တစ်မျိုးနဲ့လည်း ဒီလိုပြနိုင်တယ်။

ဂဏန်းတစ်ခုကို အဲဒီဂဏန်းနဲ့ပဲ ထပ်ခါထပ်ခါ မြှောက်လာပြီဆိုရင် power ကို exponent နဲ့ စရေးလို့ရပြီ။ ဥပမာ ၂ × ၂ × ၂ × ၂ ကို ၂⁴ (၂ ရဲ့ လေးထပ်ကိန်း) လို့ ရေးနိုင်တယ်။ ၂၊ ၄၊ ၈ နဲ့ ၁၆ တို့ဟာ ၂ ကို သူ့ကိုယ်သူ ပြန်မြှောက်ပြီး ရလာတာဖြစ်လို့ ၂ ရဲ့ power တွေပဲ။ အကျဉ်းချုပ်ကို ဒီလိုလည်း ပြနိုင်တယ်။

ဒီဇယားက အခု တော်တော်ရှင်းသွားပြီ။ Code အရေအတွက်ဟာ ၂ ကို dot နဲ့ dash အရေအတွက်ထပ် တင်ထားတာနဲ့ ညီတယ်။

code အရေအတွက် = ၂^(dot နှင့် dash အရေအတွက်)

Code တွေအကြောင်းပြောတဲ့အခါ ၂ ရဲ့ power တွေ မကြာခဏ ပေါ်လာတတ်တယ်။ အထူးသဖြင့် ဒီစာအုပ်ထဲမှာ အများကြီးတွေ့ရမယ်။ နောက်အခန်းမှာ နမူနာတစ်ခု ထပ်တွေ့ရမယ်။

Morse code ကို ပိုလွယ်လွယ် decode လုပ်နိုင်ဖို့ ဒီမှာပြထားတဲ့ သစ်ပင်ကြီးပုံစံ diagram မျိုး ဆွဲထားလို့ရတယ်။

ဒီ diagram က dot နဲ့ dash တွေကို အစဉ်လိုက်ရွေးသွားတိုင်း ဘယ်အက္ခရာ ရလာမလဲဆိုတာ ပြတယ်။ Code တစ်ခုကို decode လုပ်ချင်ရင် မြားတွေကို ဘယ်ကနေညာဘက်ဆီ လိုက်သွားရုံပဲ။ ဥပမာ dot-dash-dot နဲ့ ကိုက်ညီတဲ့ အက္ခရာကို သိချင်တယ်ဆိုပါစို့။ ဘယ်ဘက်ကစပြီး dot ကို ရွေးမယ်။ ပြီးရင် မြားအတိုင်း ညာဘက်ဆက်သွားပြီး dash ကို ရွေး၊ နောက်ထပ် dot တစ်ခုကို ရွေးမယ်။ တတိယ dot ဘေးမှာ ပြထားတဲ့ R က အဖြေပဲ။

စဉ်းစားကြည့်ရင် Morse code ကို အစကတည်းက သတ်မှတ်ဖို့ ဒီလိုဇယားမျိုး တည်ဆောက်ထားဖို့ လိုခဲ့မှာပဲ။ ပထမအကျိုးကျေးဇူးက မတူတဲ့အက္ခရာနှစ်လုံးအတွက် code တစ်ခုတည်းကို မှားပြီးသုံးမိတဲ့ ရယ်စရာအမှားကို ရှောင်နိုင်တာပဲ။ ဒုတိယအချက်က dot နဲ့ dash အစီအစဉ်တွေကို မလိုအပ်ဘဲ ရှည်အောင်မလုပ်ဘဲ ဖြစ်နိုင်သမျှ code အားလုံးကို အသုံးချထားကြောင်း သေချာစေတယ်။

ဒီဇယားကို စာမျက်နှာဘောင်ကျော်သွားနိုင်တဲ့အထိ ဆက်ချဲ့ကြည့်မယ်ဆိုရင် dot နဲ့ dash ငါးခုပါတဲ့ code တွေအထိ ဆက်နိုင်တယ်။ Dot နဲ့ dash ငါးခုတိတိရှိတဲ့ အစီအစဉ်က နောက်ထပ် code ၃၂ ခု—၂ × ၂ × ၂ × ၂ × ၂၊ ဒါမှမဟုတ် ၂⁵—ပေးတယ်။ ပုံမှန်အားဖြင့် Morse code မှာ သတ်မှတ်ထားတဲ့ ဂဏန်း ၁၀ လုံးနဲ့ ပုဒ်ဖြတ်ပုဒ်ရပ် ၁၆ မျိုးအတွက် ဒီလောက်ဆို လုံလောက်သင့်တယ်။ တကယ်လည်း ဂဏန်းတွေကို dot နဲ့ dash ငါးခုနဲ့ encode လုပ်ထားတယ်။ ဒါပေမယ့် dot နဲ့ dash ငါးခုပါတဲ့ တခြား code အများအပြားက ပုဒ်ဖြတ်ပုဒ်ရပ်တွေထက် accent ပါတဲ့ အက္ခရာတွေကို ကိုယ်စားပြုထားတယ်။

ပုဒ်ဖြတ်ပုဒ်ရပ်အားလုံး ထည့်ချင်ရင် စနစ်ကို dot နဲ့ dash ခြောက်ခုအထိ ချဲ့ရမယ်။ အဲဒီအခါ နောက်ထပ် code ၆၄ ခု—၂ × ၂ × ၂ × ၂ × ၂ × ၂၊ ဒါမှမဟုတ် ၂⁶—ရလာပြီး စုစုပေါင်း ၂ + ၄ + ၈ + ၁၆ + ၃၂ + ၆၄ = ၁၂၆ လုံးအထိ ကိုယ်စားပြုနိုင်မယ်။ Morse code အတွက်တော့ ဒါဟာ လိုတာထက် အများကြီးပိုနေတယ်။ ဒါကြောင့် ရှည်တဲ့ code အတော်များများကို undefined အဖြစ် ချန်ထားတယ်။ ဒီနေရာမှာ undefined ဆိုတာ ဘာတစ်ခုကိုမှ ကိုယ်စားမပြုတဲ့ code လို့ ဆိုလိုတယ်။ Morse code လက်ခံနေတုန်း undefined code တစ်ခုရလာရင် တစ်ယောက်ယောက် မှားလိုက်ပြီလို့ စိတ်ချလက်ချ ပြောနိုင်တယ်။

ဒီဖော်မြူလာလေးကို စဉ်းစားထုတ်နိုင်လောက်အောင် ကျွန်တော်တို့ တော်ခဲ့ကြလို့၊

code အရေအတွက် = ၂^(dot နှင့် dash အရေအတွက်)

ပိုရှည်တဲ့ အစီအစဉ်တွေသုံးရင် code ဘယ်နှခုရမလဲဆိုတာ ဆက်တွက်နိုင်ပြီ။

![C.O.D.E အခန်း ၂ — ပိုရှည်တဲ့ အစီအစဉ်တွေသုံးရင် code ဘယ်နှခုရမလဲဆိုတာ ဆက်တွက်နိုင်ပြီ။](/images/blog/code-chapter-2/image10.jpg)

ကံကောင်းတာက ဖြစ်နိုင်သမျှ code အားလုံးကို တကယ်ချရေးစရာ မလိုဘူး။ ၂ ကို သူ့ကိုယ်သူ အကြိမ်ကြိမ် ပြန်မြှောက်လိုက်ရုံပဲ။

Morse code ကို binary လို့ခေါ်တယ်။ စကားလုံးရဲ့ မူရင်းအဓိပ္ပာယ်က ‘နှစ်ခုစီ’ လို့ ဆိုလိုပြီး ဒီ code ရဲ့ အစိတ်အပိုင်းမှာ dot နဲ့ dash ဆိုတဲ့ အရာနှစ်မျိုးပဲ ရှိလို့ပါ။ ဒါဟာ ခေါင်းဘက် ဒါမှမဟုတ် ပန်းဘက် နှစ်မျိုးပဲ ကျနိုင်တဲ့ အကြွေစေ့တစ်စေ့နဲ့ ဆင်တူတယ်။ အကြွေစေ့ကို ၁၀ ကြိမ်ပစ်ရင် ခေါင်းနဲ့ပန်း အစီအစဉ်ပေါင်း ၁၀၂၄ မျိုး ဖြစ်နိုင်တယ်။

အကြွေစေ့လို binary အရာတွေကို ပေါင်းစပ်တာဖြစ်ဖြစ်၊ Morse code လို binary code တွေကို ပေါင်းစပ်တာဖြစ်ဖြစ် ဖြစ်နိုင်တဲ့အရေအတွက်ကို ၂ ရဲ့ power တွေနဲ့ အမြဲဖော်ပြနိုင်တယ်။ ၂ ဟာ ဒီစာအုပ်ထဲမှာ အလွန်အရေးကြီးတဲ့ ဂဏန်းတစ်ခုပါပဲ။
